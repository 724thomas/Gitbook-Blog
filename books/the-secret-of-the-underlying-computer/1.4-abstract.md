# 1.4 Abstract

### 1. 프로그래밍과 추상화

#### 1) 개념 정의

프로그래밍에서의 추상화란, 복잡한 동작이나 데이터의 불필요한 세부 사항을 감추고 사용자가 알아야 할 핵심 인터페이스만 노출하는 기법이다.

#### 2) 원리 설명

컴퓨터는 본질적으로 0과 1을 처리하는 기계이지만, 사람이 매번 비트 단위로 사고하면서 프로그램을 작성하기는 어렵다. \
그래서 우리는 "이 코드가 안에서 정확히 어떻게 동작하는가"보다 "이 코드에 무엇을 넣으면 무엇이 나오는가"라는 관점으로 문제를 다룬다. \
이렇게 내부를 가리고 외부 사용 방법만 드러내는 것이 추상화이며, 덕분에 프로그래머는 한 번에 한 가지 추상화 수준에만 집중할 수 있다. \
프로그래밍 언어 자체가 이미 거대한 추상화 계층이고, 그 위에서 우리가 정의하는 함수·변수·자료형도 모두 같은 원리를 작은 규모로 반복한 것이다. \
결과적으로 추상화는 사람이 다룰 수 있는 복잡도의 한계를 끌어올려 주는 도구다.

#### 3) 세부 메커니즘

프로그래밍 언어 자체가 여러 층의 추상화로 쌓여 있다.&#x20;

* 가장 아래에는 CPU가 직접 실행하는 기계어(0과 1의 나열)가 있고,&#x20;
* 그 위에 사람이 기호로 읽을 수 있게 만든 어셈블리어가 있으며,&#x20;
* 다시 그 위에 C·자바·파이썬 같은 고급 언어가 있다.&#x20;

위 계층으로 올라갈수록 한 줄의 의미가 커지고, 아래 계층의 세부 사항(레지스터, 메모리 주소, 명령어 순서 등)은 점점 가려진다. \
또한 같은 언어 안에서도&#x20;

* 변수는 "값을 담아두는 상자" 정도로,&#x20;
* 함수는 "어떤 입력에 대해 어떤 출력을 만드는 절차"로,&#x20;
* 타입은 "어떤 종류의 값을 다루고 있는지"

를 이름 하나로 묶어 가려 준다. \
즉, 추상화는 "이름 붙이기 + 내부 숨기기"라는 같은 패턴을 언어 차원과 사용자 코드 차원에서 반복하여 작동한다.

#### 4) 예시

**예시 1: 함수에 의한 추상화**

아래 코드에서 호출자는 `add` 안에서 덧셈이 어떤 CPU 명령으로 처리되는지 알 필요가 없다. 단지 "두 정수를 넣으면 합이 나온다"는 약속만 알면 된다.

```c
int add(int a, int b) {
    return a + b;
}

int main(void) {
    int s = add(3, 5);   // 내부 구현은 몰라도 결과가 8임을 안다
    return 0;
}
```

`add`라는 이름 뒤에 구현 세부가 숨어 있고, 사용자는 인터페이스(입력 두 개, 출력 한 개)만 본다.

**예시 2: 언어 계층의 추상화**

고급 언어에서 `c = a + b;`라고 한 줄로 쓰는 작업은, 어셈블리 수준에서는 대략 다음과 같이 여러 단계로 펼쳐진다.

```asm
mov eax, [a]    ; 메모리에서 a의 값을 레지스터로 가져온다
add eax, [b]    ; 그 레지스터에 b의 값을 더한다
mov [c], eax    ; 결과를 메모리의 c 위치에 저장한다
```

고급 언어를 쓰는 프로그래머는 "어느 레지스터를 쓸지", "메모리에서 언제 값을 가져올지" 같은 세부 사항을 의식하지 않아도 된다. \
언어가 이 디테일을 대신 가려 주기 때문이다.



프로그래밍 한 줄, 함수 하나에서 일어나는 이러한 "숨기고 드러내기"의 원리는, 규모가 커지면 모듈·계층·인터페이스를 통해 시스템 전체를 설계하는 원리로 확장된다. ("시스템 설계와 추상화")

***

### 2. 시스템 설계와 추상화

#### 1) 개념 정의

컴퓨터 시스템은 하드웨어부터 애플리케이션까지 여러 계층의 추상화를 차곡차곡 쌓아 올린 구조이며, 각 계층은 아래 계층의 복잡한 세부를 숨기고 위 계층에게 깔끔한 인터페이스만 제공한다.

#### 2) 원리 설명

하나의 컴퓨터가 작은 회로 소자들로부터 웹 브라우저 같은 거대한 응용 프로그램까지 동시에 돌아갈 수 있는 비결은 "계층화된 추상화"에 있다.&#x20;

* 가장 아래에는 트랜지스터와 논리 게이트 같은 물리적 회로가 있고,&#x20;
* 그 위에 CPU·메모리 같은 하드웨어 단위,&#x20;
* 다시 그 위에 운영체제, 라이브러리,&#x20;
* 그리고 최상위에 응용 프로그램이 올라간다.&#x20;

각 계층은 바로 아래 계층만 알면 되고, 더 아래의 세부는 알 필요가 없다.&#x20;

즉 위 계층은 아래 계층을 "이렇게 쓰면 된다"는 약속(인터페이스)으로만 다루며, 아래 계층이 어떻게 구현되었는지는 신경 쓰지 않는다. \
이 덕분에 한 사람이 모든 계층을 다 이해하지 않아도 거대한 시스템을 만들고 유지할 수 있다.

#### 3) 세부 메커니즘

이 계층화의 핵심은 "각 계층이 위 계층에게 무엇을 약속하는가"에 있다. \
예를 들어&#x20;

* 운영체제는 응용 프로그램에게 "파일은 열고 읽고 쓰는 것",&#x20;
* "네트워크는 소켓을 통해 보내고 받는 것"

이라는 단순한 추상을 제공한다. \
응용 프로그램 입장에서는 디스크가 SSD인지 HDD인지, 네트워크 카드가 어떤 모델인지 알 필요가 없다. \
또한 운영체제는 "마치 내 프로그램이 컴퓨터를 혼자 쓰는 것 같은" 환경을 만들어주어, 프로그래머가 다른 프로그램의 존재를 신경 쓰지 않고 코드를 짤 수 있게 해준다. \
결과적으로 어느 한 계층이 바뀌어도(예: 디스크를 HDD에서 SSD로 교체) 위 계층의 코드는 그대로 작동한다.

#### 4) 예시

**컴퓨터 시스템 계층도 (개략):**

```
┌─────────────────────────────────────────┐
│  응용 프로그램 (브라우저, 게임, 에디터)    │
├─────────────────────────────────────────┤
│  라이브러리 (표준 라이브러리, 프레임워크)  │
├─────────────────────────────────────────┤
│  운영체제 (파일, 소켓, 메모리 관리)        │
├─────────────────────────────────────────┤
│  하드웨어 (CPU, 메모리, 디스크, NIC)      │
├─────────────────────────────────────────┤
│  논리 게이트 (AND, OR, NOT)              │
├─────────────────────────────────────────┤
│  트랜지스터 (물리 회로)                   │
└─────────────────────────────────────────┘
```

**파일을 읽는 단순한 코드:**

```c
FILE *fp = fopen("hello.txt", "r");
fread(buf, 1, 100, fp);
fclose(fp);
```

이 몇 줄짜리 코드 뒤에서는 라이브러리가 운영체제에 시스템 콜을 보내고, 운영체제가 파일시스템을 거쳐 디스크 컨트롤러에게 명령을 내리고, 디스크가 실제 데이터를 읽어 올린다. \
프로그래머는 이 모든 과정을 몰라도 `fopen`이라는 추상화만 사용하면 된다.



"프로그래밍과 추상화"가 함수·모듈처럼 코드 내부에서 복잡함을 감추는 방법이었다면, "시스템 설계와 추상화"는 그 원리가 컴퓨터 시스템 전체로 확장된 모습이다. \
같은 "세부를 숨기고 인터페이스만 노출"한다는 원리가 한 줄의 함수 호출에서부터 운영체제 전체에 이르기까지 똑같이 적용된다.
